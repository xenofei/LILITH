# M0 Spikes Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Install and pin the toolchain, then prove or disprove each risky assumption the M1a plans depend on, leaving a dated decision record for every open choice the spec hands to M0.

**Architecture:** Each spike is a small throwaway program under `spikes/<name>/` with a scripted measurement that writes JSON into `spikes/<name>/results/`. A results document `docs/spikes/<nn>-<name>.md` records the setup, measurements, verdict against pre-written pass criteria, and the decision. Spike code never becomes product code: plans 1–6 re-implement what they need properly. The final task rolls the decisions into the spec, which the owner reviews.

**Tech Stack:** Rust (stable, MSVC target), CMake + Ninja, MSVC (VS 2022 Build Tools 17.14), Qt 6.12 LTS + Qt WebEngine (matching release), cxx-qt 0.10, KDDockWidgets 2.4.1, QRhi / `qsb`, Python 3.14 for the ComfyUI measurement harness, the local ComfyUI 0.39.2.

**Spec:** `docs/superpowers/specs/2026-10-12-lilith-design.md` (rules cited by ID). Roadmap: `docs/superpowers/plans/2026-10-12-roadmap.md`.

## Global Constraints

- **Ask the owner first:** every install, every model download, any download over 2 GB, and the ComfyUI PyTorch CUDA 13 upgrade. State the name, source, size and what it changes, then wait for a clear yes.
- **Pins:**
  - Qt 6.12 LTS with the matching Qt WebEngine release; if the stack fails on 6.12, fall back to Qt 6.11 (ARCH-115);
  - cxx-qt 0.10;
  - KDDockWidgets 2.4.1, Qt Quick frontend;
  - MSVC from VS 2022 Build Tools.
- **Rendering:** Qt Quick defaults to Direct3D 11. D3D12 is only measured here (IMG-033, IMG-152).
- **ComfyUI:** at `%USERPROFILE%\ComfyUI` (0.39.2, frontend 1.53.10, torch 2.11 cu128), listening on loopback `http://127.0.0.1:8188` only (ARCH-068). Spikes attach to it and never start it on another address. They never cancel jobs they didn't submit (ARCH-069).
- **GPU:** the test machine's RTX 5080, 16 GB (16,303 MiB), driver 610.88. System RAM is well above the model set (> 64 GB).
- **Isolation:** spikes never write to `%APPDATA%\Worldwright`, `%LOCALAPPDATA%\Worldwright`, Credential Manager, HKCU suite keys or the user's workspace (`<workspace>`). They use their own temp folders and their own Task Scheduler task name, `WorldwrightSpikeTask`, which is deleted at the end.
- **No secrets** in any file, log or commit.
- **Git:** work on branch `m0-spikes` in a local clone of the suite repository (`<repo>`). Commit after each task, ending every message with `Co-Authored-By: Claude Opus 5.5 <noreply@anthropic.com>`. Push nothing until the owner asks; the merge guard comes in plan 1.
- **Measurements:**
  - all timings in milliseconds, all memory in MiB;
  - each measured series reports n, p50, p95, p99 and max;
  - raw samples go in the JSON;
  - the GPU/driver/ComfyUI/Qt versions go at the top of every results document.

## Review Focus

1. **A floated or re-docked canvas loses its GPU renderer.** The canvas must rebuild from the CPU tiles without a crash or a blank view (ARCH-116, IMG-038). Task 3 tests this by forcing the renderer to be destroyed and recreated.
2. **ComfyUI is not running when the WebEngine tab or the measurement harness starts.** Each must report "ComfyUI unreachable at 127.0.0.1:8188" and exit cleanly, never hang. Tasks 6 and 8 each include this negative check.
3. **ComfyUI runs out of VRAM, or silently falls back to system memory, during a measurement.** That must be detected and recorded as a failed configuration, not reported as slow-but-fine (ARCH-072). Task 8 checks the run time against 3× the expected time and greps the log for OOM and offload messages.
4. **The deployed app is run with no Qt on PATH.** `windeployqt` output must start on its own; a missing plugin (WebEngine resources, the D3D compiler, `qsb` shaders) is the most likely failure. Task 2 runs the deployed folder with a PATH stripped of every Qt and MSVC directory.
5. **A paste target gets text instead of the image, or Explorer moves the source file.** APP-068 and APP-069 forbid both. Task 7 checks each target app and the drag result.

- Create: `spikes/canvas/run-composite-check.ps1`, which writes `results/composite.json`.

**Interfaces:**
- Consumes: Task 2's app skeleton and logging (`--log`).
- Produces: `spikes/canvas/canvas.exe` with these switches, which Task 4 uses:
  - `--layers N`
  - `--doc WxH`
  - `--backend d3d11|d3d12` (sets `QSG_RHI_BACKEND`)
  - `--golden <dir>`
  - `--frames N`
  - `--frametimes <json>`
  - `--recreate-every N` (destroys and recreates the renderer every N frames)
  - `--auto-pan` (pans continuously at 1,000 px/s, bouncing at the document edges)
  - `--trim-flag <path>` (whenever that file's modification time changes, trims the GPU tile cache to the visible pages; this stands in for IMG-040's "trim on submit")

**Algorithm (decided here; the shader code is the implementer's):**
- **Layer tiles** are 128×128 RGBA8 textures. They are bound only as sampled textures, through a texture array plus a storage-buffer slot table that maps (layer, tile) → array slice (IMG-031).
- **Composite pass:** one compute dispatch per 128×128 output tile. Each invocation loops over the layers bottom to top in registers, applies the blend (normal, multiply, screen, overlay, plus opacity and visibility), and writes the result to the projection texture exactly once. Nothing in this pass reads the projection (IMG-030).
- **Isolated groups:** the group is composited first into an intermediate texture (pass 1), which the parent pass (pass 2) samples as a single layer (IMG-031).
- **Adjustment layer:** a curves adjustment, bound as a 256×1 lookup texture.
- **Mips:** each level is generated into a **separate texture** from the level above (IMG-032). The display shader picks the level and filters between levels.
- **sRGB handling:** textures are created without the sRGB flag, so blending happens in encoded sRGB (IMG-035).

- [ ] **Step 1: Write the pass criteria into `03-canvas-compositing.md`:**
  1. The GPU and CPU composites of the golden scene differ by at most 1/255 per channel on every pixel. The golden scene is 6 layers with 4 blend modes, one isolated group of 2 layers, one curves adjustment and partial opacity, on a 1024×1024 canvas.
  2. No compute pipeline both reads and writes the same texture. Verify with the D3D11 debug layer enabled (`QSG_RHI_DEBUG_LAYER=1`): no errors or warnings about resource hazards.
  3. Each mip level matches a CPU box-filter downsample of the level above to within 1/255.
  4. With `--recreate-every 120 --frames 1200`, all 10 recreations rebuild the view (frame 1200 matches golden criterion 1), with no crash or device-removed error.
  5. Criteria 1–4 are also run with `--backend d3d12`, and the results are recorded separately.

- [ ] **Step 2: Write `run-composite-check.ps1`** (it runs `canvas.exe --golden spikes/canvas/golden --backend d3d11`, then compares the read-back projection with the CPU output). Run it before the shaders exist.

### Task 6: WebEngine ↔ ComfyUI frontend scripting (IMG-159, IMG-127, IMG-129, ARCH-070)

- [ ] **Step 1: Write the pass criteria:**
  1. `loadGraph` opens the fixture **in a new workflow tab** without replacing the user's current tab, and the flag reads `ok` within 3 s. The graph is passed as base64 and decoded in the page; there is no string-built script.
  2. `readGraph` returns JSON whose node ids and links equal the loaded fixture, and an `extra.worldwright` stamp added before loading survives the round-trip (IMG-128).
  3. **Hidden conversion page:** a second `QWebEngineView`, never shown, with its own off-the-record `QWebEngineProfile`, loads ComfyUI and converts both fixtures. Its `output` equals what ComfyUI's own "Export (API)" produces for the same fixtures, compared as JSON after sorting keys.
  4. **State isolation:** the hidden page leaves ComfyUI's saved state alone. Snapshot `%USERPROFILE%\ComfyUI\user\default\` (file list, hashes, and `comfy.settings.json` content) before and after 10 hidden conversions; the snapshots must be identical. If they aren't, record exactly which files changed. That decides IMG-124's fallback ("Run in ComfyUI tab").
  5. **Downloads blocked:** triggering a download in the page (ComfyUI's "Export" → file) is cancelled in `QWebEngineProfile::downloadRequested`, `downloadAttempts` increments, and no file appears in the user's Downloads folder.
